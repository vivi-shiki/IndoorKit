# IndoorKit — 病院内位置情報デモ

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語**

IndoorKit は、MapLibre GL JS と TypeScript で開発した屋内地図 SDK です。このリポジトリには、ブラウザ上で動作する病院向けリアルタイム位置情報システム（RTLS）のデモを収録しています。

**オンラインデモ：<https://vivi-shiki.github.io/IndoorKit/?lang=ja>**

人物・機器・建物はすべて架空です。施設は「さくら総合病院」で、5 階建ての 3 棟が各フロアの連絡通路でつながっています。

## 部門

このデモでは、診療・看護・事務・サービス用の各部屋を部門（救急科、内科、外科、集中治療科など）に割り当てています。1 つの部門が複数の部屋・棟・フロアにまたがる場合もあります。人と機器にも所属部門を設定しています。廊下、エレベーター、トイレなどの共用スペースは、どの部門にも割り当てていません。

アラートは、部門エリア、エリア検知、機器・人の状態の 3 種類に分類されます。測位データを受信すると、エンジンは部門エリア、エリア検知、機器のオフラインや SOS 発報などの状態の順に確認します。

1. **部門エリア**：患者が所属部門エリア外に 30 秒以上いる、面会者が面会先以外の部門エリアに進入する、機器が所属部門から持ち出される、など。
2. **エリア検知**：所属部門に応じた ICU の立入制限、1 階出入口エリアへの機器進入、病室での面会者の滞在時間超過。
3. **機器・人の状態**：機器オフライン、人からの SOS 発報。

## 医療機器

### 医療機器の所在・稼働状況

部屋ごとの医療機器の所在、稼働状況、本日の稼働時間を表示します。稼働中・待機中・オフライン・メンテナンス中の状態は、機器ごとに設定した状態スケジュールで模擬しています。

- 各部屋を 1 つの集約マーカーで表示し、マーカーの色には、その部屋の機器のうち表示優先度が最も高い状態を反映します。
- 部門の一覧に、部門ごとの台数と、オフライン・メンテナンス中の台数を表示します。部門を選ぶとその部屋を強調し、一覧に表示します。
- 部屋をクリックすると中の機器を、機器をクリックすると状態、その状態の継続時間、本日の稼働時間、電池残量、本日の状態推移を表示します。
- 機器の番号や種類で検索し、状態や種類で絞り込めます。

![医療機器の所在・稼働状況](docs/images/assets.png)

## 人の所在

### 所在確認

いま誰がどこにいるかを表示します。人の移動をシミュレーションし、廊下や出入口に沿って移動させます。フロア間の移動にはエレベーターまたは階段を使います。

- 対象者の区分（医師、看護師、患者、面会者、看護補助者、警備員）ごとに色分けし、区分で絞り込めます。
- 部門ごとに対象者を一覧表示し、所属部門エリア外にいる人数も表示します。
- 氏名や ID で検索して結果を選ぶと、その人のフロアに移動して位置を追跡します。人物カードには所属部門、所在地、所属部門エリア内にいるかどうかを表示し、そこから移動履歴を再生できます。
- シミュレーションのタグ数は 500・2,000・5,000 から選べます。位置は毎秒更新され、更新の間も滑らかに動きます。パフォーマンスパネルにフレームレート、フレーム間隔、受信済みタグ数を表示します。

![所在確認](docs/images/tracking.png)

### 移動履歴の再生

その人がこれまでどこにいたかを表示します。対象者と直近 15 分・30 分・60 分のいずれかの期間を選び、1 倍・4 倍・16 倍の速度で移動履歴を再生できます。

- 再生中は人の移動に合わせて地図のフロアも切り替わります。
- 滞在場所を時刻・部屋・滞在時間とともに一覧表示し、所属部門エリア外なら印を付けます。クリックするとその時刻に移動します。
- 滞在場所の下に、経路上のアラートを一覧表示します。

![移動履歴の再生](docs/images/trail.png)

### アラート一覧

部門エリア・エリア検知・機器と人の状態の 3 種類のアラートを 1 つの一覧にまとめ、アラートの対象となる人や機器、発生場所、種類、重大度を表示します。

- 各アラートを「確認済み」または「解決済み」に変更でき、種類で絞り込めます。
- アラートの人や機器をクリックすると、そのフロアと位置に移動します。

![アラート一覧](docs/images/alerts.png)

### 測位ヒートマップ

直近 1・5・15 分の各フロアの位置記録数を対象者の区分ごとに表示し、そのフロアで位置記録数の多い部屋を 3 つ挙げます。色は位置記録数を表し、現在の人数を表すものではありません。

![測位ヒートマップ](docs/images/occupancy.png)

### 全ページ共通

- フロア切替（1F～5F）。全棟が同時に切り替わります。
- 日本語・英語・中国語に対応し、地図内の部屋名も切り替わります。
- 両テーマとも、文字のコントラストは WCAG AA を設計目標としています。現在の確認範囲は[コントラストテスト](apps/playground/e2e/theme-contrast.spec.ts)を参照してください。
- 言語とテーマはブラウザに保存され、次回もそのまま表示されます。

## 技術的なポイント

- **プラグイン機構を持つ屋内地図 SDK。** `definePlugin` でプラグインと依存関係を宣言すると、依存順に読み込まれます。プラグイン API の型は依存関係に基づいて推論されます（例：`map.plugins.alarm.alarms()`）。
- **リソースの登録と解放。** プラグインが作ったソース、レイヤー、リスナー、タイマー、Worker はすべて `ResourceTracker` に登録され、`destroy()` で作成と逆順に解放されます。メモリ回帰テストでは全ページを繰り返し切り替え、JS ヒープ、Worker、登録済みリソースを確認します。
- **オープンなデータ形式。** 地図データは IMDF（OGC コミュニティ標準）で、要素間の参照や ID の一意性も含めて zod で検証します。部門は IMDF の拡張ファイルで、部門ごとの部屋を列挙します。存在しない部屋への参照や、同じ部屋の複数部門への割り当ては、検証エラーとして扱います。架空の病院はスクリプトで生成するため、データを再現できます。
- **データからスタイルを生成。** 部屋の色と 2.5D の高さは部屋の種類とテーマで決まり、壁と部屋は `fill-extrusion` で立体化するので 3D モデルは不要です。言語とテーマは地図を作り直さずに切り替わります。
- **測位シミュレーションを Web Worker で実行。** シード付きで再現可能な測位シミュレーターを Web Worker で動かし、Comlink でページとやり取りします。同じ ID は常に同じ人・同じ機器で、区分、部門、状態のスケジュールも変わりません。
- **2 層のアラートエンジン。** 位置が届くたびに、まず部門エリア（猶予時間を超えて所属部門エリア外にいる、他部門エリアへの進入）、次にエリア検知（立入制限エリアへの侵入、滞在時間超過、エリアからの離脱）で判定します。部門ごとに対象外にもできます。エリアのルール違反が続いている間は、同じルールのアラートを繰り返し発生させません。違反状態が解消すると、再度の違反を検知できる状態に戻ります。オフラインと SOS 発報は状態変化として別に判定します。
- **空間アルゴリズム。** Flatbush インデックスと点の多角形内判定で、位置ごとの部屋と部門を求めます。移動は補間して表示し、移動履歴の記録と滞在場所の検出に対応します。機器は部屋と状態ごとに集約します。ヒートマップはサンプルを分単位・グリッド単位で集計し、メモリ使用量を一定の範囲に抑えます。
- **単体テストと E2E テスト。** 単体テストは WebGL を使わないインメモリのモックマップで SDK を動かします。Playwright はテスト用フックで実際のページを操作し、両テーマのコントラストを確認し、Chrome DevTools Protocol でヒープの増加を計測します。GitHub Actions ですべてのテストを実行し、GitHub Pages にデプロイします。

## ディレクトリ構成

| パス | 内容 |
| --- | --- |
| `packages/core` | 地図エンジンのラッパー：地図の生成、カメラ、プラグイン機構、リソース管理、イベント、スタイルとテーマの生成。MapLibre を読み込むのはこのパッケージだけ |
| `packages/imdf` | IMDF の読み込み・検証・変換。標準外のデータは拡張ファイルとして扱う |
| `packages/rtls` | リアルタイム測位の契約：タグの位置、データプロバイダー、`positions:update` イベント |
| `packages/plugins` | フロア、ゾーン、リアルタイム位置、部屋単位の集約、軌跡、クラスタ、ジオフェンス（エリア検知）、ヒートマップ、多角形、線、ポップアップ、マーカーの各プラグイン。病院の概念は含まない |
| `domains/hospital` | 地図に依存しない病院の業務：部門（IMDF 拡張）、対象者の区分、機器と状態、2 層のアラートエンジン |
| `tools/venue-gen` | 架空の病院とその部門の生成スクリプト |
| `tools/rtls-simulator` | 人と機器の名簿、移動シミュレーター、Worker 用データプロバイダー |
| `apps/playground` | オンラインデモ（React と MUI）。トップページで 3 つの活用シーンを紹介し、病院デモの 5 ページはサイドバー（スマホでは上部メニュー）で切り替えます。`engine/` が MapLibre を読み込み、`adapters/` が病院の業務とシミュレーターを SDK のプラグインにつなぎ、`presentation/` が文言と色、`pages/` が各ページ、`testing/` がテスト用フック |

## ローカルで動かす

Node.js 22 と pnpm が必要です。

```bash
pnpm install
pnpm build
pnpm --filter playground preview
```

<http://localhost:4173/IndoorKit/> を開いてください。
