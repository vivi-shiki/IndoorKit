# IndoorKit — 病院内の位置情報マップ

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語**

ブラウザだけで動く、病院向けの屋内測位（RTLS）のデモです。土台には、MapLibre GL JS の上に TypeScript でゼロから作った屋内地図 SDK を使っています。

**オンラインデモ：<https://vivi-shiki.github.io/IndoorKit/?lang=ja>**

人物・機器・建物はすべて架空です。施設は「さくら総合病院」で、5 階建ての 3 棟が各フロアの連絡通路でつながっています。

## 診療科

すべての部屋はいずれかの診療科（救急科、内科、外科、集中治療科など）に属します。1 つの診療科は複数の部屋を持ち、棟やフロアをまたぐこともあります。機器と人もそれぞれ 1 つの診療科に属します。廊下、エレベーター、トイレなどは共用エリアで、どの診療科にも属しません。

アラートはまず診療科エリアを見て、次にジオフェンスを見ます。

1. **診療科エリア**：患者が所属の診療科の外に 30 秒以上いる、面会者が面会先以外の診療科に入る、機器が所属の診療科から持ち出される、など。
2. **ジオフェンス**：ICU の立入制限（ICU 所属のスタッフのみ入室可）、1F 出入口での機器の持ち出し防止、病室の面会時間。
3. **送信される状態**：機器のオフライン、人の緊急呼び出し（SOS）。

## 機器ビュー

### 機器マップ

どの部屋にどの機器があり、いまどの状態で、今日どれだけ稼働したかを表示します。稼働状態（稼働中・待機・オフライン・保守中）は機器から送信されるもので、ここでは機器ごとのスケジュールで模擬しています。

- 機器は部屋ごとにまとめ、部屋ごとに 1 つの点を表示します。点の色は部屋の中で最も重い状態です。
- 診療科の一覧に、診療科ごとの台数と、オフライン・保守中の台数を表示します。診療科を選ぶとその部屋を強調し、一覧に表示します。
- 部屋をクリックすると中の機器を、機器をクリックすると状態、その状態の継続時間、今日の稼働時間、電池残量、今日の状態のタイムラインを表示します。
- 機器の番号や種類で検索し、状態や種類で絞り込めます。

![機器マップ](docs/images/assets.png)

## 人の位置・移動

### 現在地マップ

いま誰がどこにいるかを表示します。タグは廊下を歩き、ドアから部屋に出入りし、フロア移動はエレベーターか階段だけで行います。

- 人物区分（医師、看護師、患者、面会者、介護士、警備員）ごとに色分けし、人物区分で絞り込めます。
- 診療科ごとに人を一覧し、所属診療科外にいる人数も表示します。
- 氏名や ID で検索すると、その人のフロアに移動して追跡します。人物カードには所属の診療科、現在地、所属診療科内にいるかどうかを表示し、そこから軌跡を開けます。
- タグ数は 500・2,000・5,000 から選べます。位置は毎秒更新され、更新の間も滑らかに動きます。パフォーマンスパネルにフレームレート、フレーム間隔、オンラインのタグ数を表示します。

![現在地マップ](docs/images/tracking.png)

### 経路の振り返り

その人がこれまでどこにいたかを表示します。人と直近 15・30・60 分の範囲を選び、1×・4×・16× の速度で再生します。

- 再生中は人の移動に合わせて地図のフロアも切り替わります。
- 立ち寄った場所を時刻・部屋・滞在時間とともに一覧し、所属診療科外なら印を付けます。クリックするとその時刻に移動します。
- 立ち寄った場所の下に、経路上のアラートを一覧します。

![経路の振り返り](docs/images/trail.png)

### エリアアラート

診療科・ジオフェンス・状態の 3 種類のアラートを 1 つの一覧にまとめ、誰が、どこで、どの層の、どの重要度のアラートかを表示します。

- アラートごとに確認・対応済みにでき、層ごとに絞り込めます。
- アラートの人や機器をクリックすると、そのフロアと位置に移動します。

![エリアアラート](docs/images/alerts.png)

### 位置情報ヒートマップ

直近 1・5・15 分の各フロアの測位回数を人物区分ごとに表示し、そのフロアで測位回数の多い部屋を 3 つ挙げます。測位回数は位置の分布を表すもので、人数とは一致しません。

![位置情報ヒートマップ](docs/images/occupancy.png)

### 全ページ共通

- フロア切替（1F～5F）。全棟が同時に切り替わります。
- 日本語・英語・中国語に対応し、地図内の部屋名も切り替わります。
- ライト／ダークテーマ。どちらでも文字は WCAG AA のコントラストを満たします。
- 言語とテーマはブラウザに保存され、次回もそのまま表示されます。

## 技術的なポイント

- **プラグイン機構を持つ屋内地図 SDK。** `definePlugin` でプラグインと依存関係を宣言すると、依存順に読み込まれ、プラグイン API には完全な型が付きます（例：`map.plugins.alarm.alarms()`）。
- **設計段階からメモリリークを防止。** プラグインが作ったソース、レイヤー、リスナー、タイマー、Worker はすべて `ResourceTracker` に登録され、`destroy()` で作成と逆順に解放されます。メモリ回帰テストでは全ページを繰り返し切り替え、JS ヒープ、Worker、登録済みリソースを確認します。
- **オープンなデータ形式。** 地図データは IMDF（OGC コミュニティ標準）で、要素間の参照や ID の一意性も含めて zod で検証します。診療科は IMDF に追加したファイルで、診療科ごとの部屋を列挙します。存在しない部屋や、2 つの診療科に属する部屋は検証で弾きます。架空の病院はスクリプトで生成するため、データを再現できます。
- **データからスタイルを生成。** 部屋の色と 2.5D の高さは部屋の種類とテーマで決まり、壁と部屋は `fill-extrusion` で立体化するので 3D モデルは不要です。言語とテーマは地図を作り直さずに切り替わります。
- **リアルタイムデータはメインスレッドの外で処理。** シード付きで再現可能な測位シミュレーターを Web Worker で動かし、Comlink でページとやり取りします。同じ ID は常に同じ人・同じ機器で、役割、診療科、状態のスケジュールも変わりません。
- **2 層のアラートエンジン。** 位置が届くたびに、まず診療科のルール（猶予時間を超えて所属診療科外にいる、他の診療科に入る）、次にジオフェンス（立入禁止、滞在超過、エリアからの退出）で判定します。診療科ごとに対象外にもできます。同じ出来事は 1 回だけアラートを出し、戻ったらリセットします。
- **空間アルゴリズム。** Flatbush インデックスと点の多角形内判定で、位置ごとの部屋と診療科を求めます。軌跡履歴と滞在検出付きの補間移動、部屋と状態ごとの集約、サンプルを「分 × グリッド」で集計してメモリ使用量に上限を設けたヒートマップ。
- **E2E までテスト。** 単体テストは WebGL を使わないメモリ上の偽の地図で SDK を動かします。Playwright はテスト用フックで実際のページを操作し、両テーマのコントラストを確認し、Chrome DevTools Protocol でヒープの増加を計測します。GitHub Actions ですべてのテストを実行し、GitHub Pages にデプロイします。

## ディレクトリ構成

| パス | 内容 |
| --- | --- |
| `packages/core` | 地図エンジンのラッパー：地図の生成、カメラ、プラグイン機構、リソース管理、イベント、スタイルとテーマの生成。MapLibre を読み込むのはこのパッケージだけ |
| `packages/imdf` | IMDF の読み込み・検証・変換。標準外のデータは拡張ファイルとして扱う |
| `packages/rtls` | リアルタイム測位の契約：タグの位置、データプロバイダー、`positions:update` イベント |
| `packages/plugins` | フロア、ゾーン、リアルタイム位置、部屋単位の集約、軌跡、クラスタ、ジオフェンス、ヒートマップ、多角形、線、ポップアップ、マーカーの各プラグイン。病院の概念は含まない |
| `domains/hospital` | 地図に依存しない病院の業務：診療科（IMDF 拡張）、役割、機器と状態、2 層のアラートエンジン |
| `tools/venue-gen` | 架空の病院とその診療科の生成スクリプト |
| `tools/rtls-simulator` | 人と機器の名簿、移動シミュレーター、Worker 用データプロバイダー |
| `apps/playground` | オンラインデモ（React と MUI）。トップページで 3 つの活用シーンを紹介し、病院デモの 5 ページはサイドバー（スマホでは上部メニュー）で切り替えます。`engine/` が MapLibre を読み込み、`adapters/` が病院の業務とシミュレーターを SDK のプラグインにつなぎ、`presentation/` が文言と色、`pages/` が各ページ、`testing/` がテスト用フック |

## ローカルで動かす

Node.js 22 と pnpm が必要です。

```bash
pnpm install
pnpm build
pnpm --filter playground preview
```

<http://localhost:4173/IndoorKit/> を開いてください。
