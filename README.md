# IndoorKit — Hospital RTLS Console

**English** | [简体中文](README.zh-CN.md) | [日本語](README.ja.md)

A demo of indoor positioning (RTLS) and asset management for a hospital, running entirely in the browser. It is built on an indoor map SDK written from scratch in TypeScript on top of MapLibre GL JS.

**Live demo: <https://vivi-shiki.github.io/IndoorKit/?lang=en>**

All people, equipment and buildings are fictional. The venue is "Sakura General Hospital": 3 buildings with 5 floors each, connected by bridges on every floor.

## What the demo shows

### Real-time Tracking

Live positions of staff, patients and equipment across the hospital. Tags walk along corridors, enter rooms through doors and change floors only by elevator or stairs.

- Choose 500, 2,000 or 5,000 tags; positions are reported once per second and glide smoothly between reports.
- Click a tag to replay its trail for the last 10 minutes.
- A performance panel shows frame rate, frame interval and tags online.

![Real-time Tracking](docs/images/tracking.png)

### Asset Distribution

Where equipment is concentrated on each floor. Nearby items (within 3 m) merge into one cluster point labelled with how many items it holds, and the header shows the cluster and asset counts for the floor.

![Asset Distribution](docs/images/assets.png)

### Restricted Zone Alerts

The ICU on 3F is a restricted area. When a tag enters or leaves it, the alert appears in the list and as a popup at the tag's position.

![Restricted Zone Alerts](docs/images/alerts.png)

### Occupancy Heatmap

Crowded areas on each floor over the last 1, 5 or 15 minutes, for planning staff and spotting congestion.

![Occupancy Heatmap](docs/images/occupancy.png)

### On every page

- Floor switching (1F–5F) across all buildings at once.
- Chinese, English and Japanese, including the room names drawn inside the map.
- Light and dark themes; text meets WCAG AA contrast in both.
- Language and theme are remembered in the browser for the next visit.

## Technical highlights

- **Indoor map SDK with a plugin system.** `definePlugin` declares a plugin and its dependencies; plugins load in dependency order and their APIs are fully typed (`map.plugins.cluster.clusters()`).
- **No leaks by design.** Every source, layer, listener, timer and Worker a plugin creates is registered with a `ResourceTracker` and released in reverse order by `destroy()`. A memory regression test switches through all pages repeatedly and checks the JS heap, Workers and registered resources.
- **Open data format.** Maps use IMDF (OGC Community Standard), validated with zod, including references between features and unique ids. The fictional hospital is generated by a script, so the data is reproducible.
- **Styles generated from data.** Room colors and 2.5D heights come from the room category and a theme; walls and rooms are extruded with `fill-extrusion`, no 3D models needed. Language and theme switch at runtime without recreating the map.
- **Real-time data off the main thread.** A deterministic, seeded simulator runs in a Web Worker and talks to the page through Comlink.
- **Spatial algorithms.** Interpolated movement with trail history, radius clustering with a KDBush index, geofencing with a Flatbush index plus point-in-polygon checks, and a heatmap that aggregates samples into per-minute grid buckets so memory stays bounded.
- **Tested end to end.** Unit tests run the SDK against an in-memory fake map without WebGL. Playwright tests drive the real pages through test hooks, check contrast in both themes, and measure heap growth through the Chrome DevTools Protocol. GitHub Actions runs everything and deploys to GitHub Pages.

## Tech stack

TypeScript (strict) · MapLibre GL JS · IMDF · zod · Web Worker + Comlink · KDBush · Flatbush · Turf · Vite · pnpm workspaces · Vitest · Playwright · Biome · GitHub Actions + GitHub Pages

## Project structure

| Path | Contents |
| --- | --- |
| `packages/core` | Map creation, plugin system, resource tracking, events, style and theme generation |
| `packages/imdf` | IMDF loading, validation and conversion |
| `packages/plugins` | Floor, position stream, cluster, geofence, heatmap, polygon, line, popup and marker plugins |
| `tools/venue-gen` | Generator for the fictional hospital |
| `tools/rtls-simulator` | Tag movement simulator and its Worker data provider |
| `apps/playground` | The four pages of the live demo |

## Run locally

Requires Node.js 22 and pnpm.

```bash
pnpm install
pnpm build
pnpm --filter playground preview
```

Then open <http://localhost:4173/IndoorKit/>.
