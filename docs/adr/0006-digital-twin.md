# ADR 0006: Editable digital-twin campuses

Status: accepted

The three demos gain independent `#/hospital/twin`, `#/parking/twin` and `#/museum/twin` pages. Existing operational routes remain the defaults. A shared page in `apps/playground/src/app/twin` receives a venue, metric callbacks and optional status callbacks (parking free-bay share per level, museum rooms with recent alarms); it imports no scenario package. Scenario adapters own the hospital inventory and the parking/museum simulation snapshots. A time slider selects a simulated hour; it is not a live telemetry feed.

`@indoorkit/core/twin` is an optional, dynamically imported entry point. Three.js shares MapLibre's WebGL context through a custom layer. The scene uses metre-scale glTF, +Y up, +X east, +Z south, with the venue's geographic origin recorded in its manifest. MapLibre remains responsible for navigation and the existing floor plugin remains responsible for indoor filtering. The custom layer and all listeners, requests, GPU buffers, materials, image bitmaps and shadow targets have explicit lifecycle ownership.

The representation switches into the indoor map above zoom 18.85 and back to the exterior below 18.5. The gap prevents oscillation around the threshold. Floor controls enter the indoor view directly. Exterior fitting is calculated from the campus bounds and the available desktop/mobile viewport.

Entering the indoor view leaves the local outdoor fill, terrain, landscaping, roads, context buildings and surface parking visible. Only the venue envelope and its attached bridge, entrance, rooftop markings and roof vehicles are hidden; entrance paving and ground traffic remain. The same loaded scene is restored outside, without moving or reloading the landscape. The indoor map and selected floor remain owned by the existing floor plugin.

Each scenario supplies `IndoorMode` adapters: hospital equipment, people and alarms; parking bays, devices, vehicles and alarms; museum sensors, tagged visitors, guards/security devices, current collection locations and alarms. `TwinPage` adds the existing `markerPlugin` and uses its atomic `replaceAll` API. One floor/search projection feeds the markers and the matching list. Mode, floor, time and language changes replace that data without rebuilding the map. Shared React views use the existing chips, rows, search and detail drawer; the mobile list retains the existing sheet behavior. The business selector appears only indoors. The SVG fallback preserves the site plan and offers the same business selection and details without WebGL.

Three.js standard PBR materials, hemisphere fill light, a room environment map and one directional sun provide lighting, with ACES filmic tone mapping. Quality is expressed as five render levels L0–L4, each a set of switches (model file, prop density, pixel ratio, anti-aliasing, sky, environment, shadow size and softness, outlines, Three.js indoor floors). Settings merge in three layers: level preset < site defaults from the manifest < the viewer's overrides. The policy lives in `packages/core/src/twin/policy.ts`, has no Three.js dependency and is exported from `@indoorkit/core` so pages can read it before loading the renderer. L0 loads no GLB and draws MapLibre fill-extrusions from the IMDF level outlines. Automatic chooses a level from the device and a frame governor steps down after sustained slow frames. Anti-aliasing is a WebGL context attribute: `createIndoorMap({ antialias })` passes it to MapLibre, and the page recreates the map when it changes. Rendering follows map changes; the only animation is a slow orbit after 20 s without input, outdoors, without reduced motion, and not under automation. No post-processing is used (decision of 2026-10-29). A WebGL initialization failure leaves an SVG site/indoor plan and floor controls available.

The sites are fictional offshore coordinates. A local GeoJSON campus plan is the outdoor basemap, with roads, building footprints and landscape geometry. An unrelated real-world tile map would show ocean under these campuses. No commercial tile token or third-party model request is required. This is a campus-scale model, not a city-scale photogrammetric model or a BIM construction deliverable.

`tools/venue-gen/src/twin.ts` derives footprints and principal entrances from the same IMDF archives as the indoor views and writes the committed models under `apps/playground/public/models`. `pnpm build` regenerates them. Buildings are top-level nodes carrying their IMDF building id, so focus, labels and picking use the same ids as the indoor map. Exterior objects are batched by function and material; CC0 props are GPU instances. Blender can separate a batch by loose parts when individual props are needed. The page does not offer a model download.

The asset provenance, real-plan references and Blender workflow are in [Digital twin assets](../digital-twin.md). Architecture tests allow both self-contained scenarios to use `app/twin`; they still prohibit imports between the scenarios.
