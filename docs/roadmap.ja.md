# IndoorKit 開発ロードマップ

[中文](roadmap.zh-CN.md) · [English](roadmap.en.md) · [日本語](roadmap.ja.md)

IndoorKit は、オープンソースの TypeScript 製屋内地図 SDK です。デモギャラリー、リアルタイム位置情報ダッシュボード、自然言語で地図を操作する AI アシスタントを備えます。地図データはすべて架空の病院「さくら総合病院」のもので、依存関係はすべて公開パッケージとオープンデータです。

ロードマップは 0～6 の 7 段階です。レベル 1 が**最小デモ可能版（MVP）**で、以降の各レベルは前のレベルが動作する状態の上に機能を追加し、レベル 6 で計画中の全機能が揃います。各レベル末尾の「関門」をすべて満たしてから、次のレベルに進みます。

**進捗**：レベル 0・1・2 は完了しました（2026-10-19）。レベル 2 の実装で変更した点は 2 つです。クラスタリング比較では、2 つのアルゴリズムの結果を完全に一致させるため supercluster ではなく KDBush の空間インデックスを使いました。デモ 4 の点の数は 1,000 / 5,000 / 10,000 です。二重ループでは 50,000 点のときにページが十数秒止まるためです。

## 概要

| レベル | テーマ | 完了時にデモできること |
| --- | --- | --- |

| 2 | リアルタイム測位と空間計算 | 数千のタグのリアルタイム移動、クラスタリングの前後比較、ジオフェンス警報、ヒートマップ |

## レベル 0：開発基盤

目標：「どうビルドし、どうテストし、どう公開するか」を先に固め、以降のすべての機能を同じパイプラインに通す。

- pnpm workspace によるモノレポ：`packages/core`、`packages/imdf`、`packages/plugins`、`apps/playground`、`tools/venue-gen`、`tools/leak-bench`
- TypeScript strict、Vite ライブラリモード（ESM 出力）、ESLint または Biome
- Vitest による単体テスト、Playwright による E2E テスト（Chromium）
- GitHub Actions：lint → 型チェック → テスト → ビルド → GitHub Pages へデプロイ
- 唯一の入口コマンド `pnpm verify`（lint + 型チェック + テスト）。vite / tsc を直接呼ばない
- AI 協業ルールをリポジトリに置く：`AGENTS.md`（プロジェクト構成と唯一のビルド入口）、`docs/guidelines/coding.md`（「プラグインが作成したリソースは必ず登録する」などのアーキテクチャ制約）、`docs/adr/`（アーキテクチャ決定記録）

**関門 0**：main へ push すると CI がすべて成功し、GitHub Pages で空の playground ページが開ける。

## レベル 1：最小デモ可能版（MVP）

目標：リンクを開くだけで誰でも見られる屋内地図を作り、中核設計（リソースの自動解放）が有効であることを数値で示す。

**コア（@indoorkit/core）**

- `createIndoorMap({ container, data, plugins })`：ライフサイクル init → load → ready → destroy。各段階で型付きイベントを発行
- `definePlugin`：プラグインが名前と依存関係を宣言し、依存順に読み込む。プラグイン API は TypeScript が自動推論する（`map.plugins.marker.add(...)` が完全に型付け）
- `ResourceTracker`：プラグインは `ctx.track()` で source、layer、イベントリスナーを登録し、`destroy()` 時に作成と逆順で自動解放
- `EventBus`：プラグイン間の通信はコアのイベント経由のみ
- 地図エンジン：MapLibre GL JS（npm パッケージ、ESM で読み込み、トークン不要）

**データ（@indoorkit/imdf）**

- IMDF（OGC コミュニティ標準 1.0.0、GeoJSON ベース）をディレクトリまたは zip から読み込む
- zod でバリデーターを実装（OGC に公式バリデーターがないため、自作バリデーター自体がアピールポイントになる）
- 内部モデルに変換：Venue / Building / Level / Unit / Opening / Amenity

**架空データ（tools/venue-gen）**

- パラメータから「廊下 + 両側の部屋 + 階段室 / エレベーターシャフト」のレイアウトを生成するスクリプト。MVP の規模は 1 棟 × 3 フロア
- IMDF を出力。診療科名は ja / en の 2 言語、座標は架空の場所に置く

**描画とプラグイン**

- スタイル生成器：IMDF の category とテーマ設定から MapLibre のレイヤーを生成（ライトテーマ）
- 壁と部屋は MapLibre の `fill-extrusion` で 2.5D に押し出すため、モデル素材は不要
- 日本語・中国語のラベルは MapLibre 標準のローカルフォント描画（`localIdeographFontFamily`）を使うため、MVP では CJK グリフファイルを生成しない
- `floor` プラグイン + フロア切替コントロール
- `marker` プラグイン：追加、削除、フロアごとの絞り込み

**デモギャラリー（apps/playground）**

- デモ 1「基本の地図」：架空病院の読み込み、フロア切替、マーカー追加。初回表示時間をページに表示
- デモ 2「メモリラボ」：地図の生成と破棄を繰り返し、各ラウンドのヒープサイズと未解放リソース数をリアルタイム表示

**メモリ回帰テスト（tools/leak-bench）**

- Playwright から CDP 経由で `HeapProfiler.collectGarbage` を呼んだ後、`Performance.getMetrics` の `JSHeapUsedSize` を読む
- 生成/破棄を 50 ラウンド行い、ヒープ増加が設定したしきい値を超えたら CI を失敗させる

**関門 1（MVP の受け入れ基準）**：GitHub Pages でデモ 1 とデモ 2 が開ける。フロア切替とマーカーが動作する。leak-bench が CI で成功する。README にオンラインリンクとスクリーンショットがある。

## レベル 2：リアルタイム測位と空間計算

目標：「大量のリアルタイムデータ + 空間アルゴリズム + 計測できる性能」を示す。

- ダークテーマ。UI と地図ラベルを 3 言語化（ja / en / zh）
- `DataProvider` インターフェース。標準実装は Web Worker 上の測位シミュレーター（Comlink で通信）で、数千のタグが 1Hz で位置を送信
- `position-stream` プラグイン：位置の補間による滑らかな移動、軌跡の記録と再生
- `popup`、`line`、`polygon` のオーバーレイプラグイン
- `cluster` プラグイン：supercluster を使用
- `geofence` プラグイン：flatbush の空間インデックス + turf の `booleanPointInPolygon` で、進入/退出イベントを発行
- `heatmap` プラグイン：MapLibre 標準の heatmap レイヤーで、時間枠ごとの人の密度を表示（フロアごとに平面のヒートマップ）
- パフォーマンスオーバーレイ：FPS、メインスレッド処理時間
- 架空データを 3 棟 × 5 フロアに拡大
- デモ 3「リアルタイム測位」：FPS とメインスレッド処理時間を表示
- デモ 4「1 万件規模のクラスタリング比較」：同じデータを O(n²) の二重ループと空間インデックスでクラスタリングし、両方の処理時間を表示
- デモ 7「ジオフェンスと警報」（2D 版）：進入/退出検知、警報ポップアップ、バッチごとの検知時間を表示
- デモ 10「ヒートマップ」

**関門 2**：シミュレーションタグ 5,000 個で、デモ 3 が一般的なノート PC 上で滑らかに動く（目標 50 FPS 以上、実測で判断）。デモ 4 で 2 つのアルゴリズムの実測時間の比較をページ内に表示する。

## レベル 3：ナビゲーションと複数フロア

目標：屋内地図で最も特徴的な 2 つの操作、フロアをまたぐナビゲーションと複数フロアの展開を完成させる。

- venue-gen で経路ネットワークを生成：廊下の中心線 + ドアのノード + 階段 / エレベーターによるフロア間接続。エッジは長さと `accessible` フラグを持ち、IMDF の拡張（`level_id` 付き LineString）として出力
- `route` プラグイン：ngraph.path の A* でブラウザ内で計算。エレベーター / 階段の重み付け、バリアフリーモード（階段のエッジを遮断）
- `nav-animation` プラグイン：経路に沿ったナビゲーションアニメーションとカメラ追従
- `multi-floor` プラグイン：各フロアに `fill-extrusion-base` で高さのオフセットを与えて展開ビューを作る。マウス / タッチのジェスチャーを自作し、上下スワイプでアニメーション付きのフロア切替
- `camera-sequence` プラグイン：プリセットのカメラアニメーション
- `campus-switcher`：複数キャンパスのデータソースを切り替え、切替後にメモリが元に戻る
- UI ウィジェット：方位磁針、縮尺
- 空間検索：座標が属する建物 / 部屋（flatbush インデックス）
- デモ 5「フロアをまたぐ経路探索」：探索時間と経路の長さを表示
- デモ 6「複数フロアの展開」：アニメーションのフレームレートを表示
- デモ 11「複数キャンパスの切替」：切替前後のヒープサイズを表示

**関門 3**：任意の 2 部屋間（別棟・別フロアを含む）で経路を探索でき、バリアフリーモードでは階段を通らない。経路探索の単体テストがフロア間移動と到達不能のケースをカバーする。キャンパスを 20 回往復切替した後も leak-bench が成功する。

## レベル 4：3D と画質の自動調整

目標：WebGL / three.js の技術力と、低性能端末への対応を示す。

- `@indoorkit/three`：MapLibre の CustomLayerInterface による自作の `ThreeLayer`。WebGL コンテキストを共有し、メルカトル座標とメートルを換算（MapLibre 公式の three.js サンプルに準拠）
- レイピッキング：MapLibre から渡される投影行列からレイを逆算（公式サンプルがないため自前で実装し、テストを書く）
- モデル：GLTFLoader + MeshoptDecoder（および DRACOLoader）、InstancedMesh のオブジェクトプール、建物フォーカス（他の建物を低くする）、影
- 3D プラグイン：`fence-3d`（フェンスの柱）、`sphere-3d`、`line-3d`、`models`（amenity の種類に応じて設備を自動配置）
- 素材パイプライン：CC0 / CC-BY 素材のみを使用（KayKit、Kenney、Quaternius、Poly Haven。車椅子は Poly Pizza の CC-BY 素材をクレジット表記付きで使用）。足りないエレベーターやモニターなどは Blender で自作。すべて glb に変換し、1 単位 = 1 メートル、原点を底面中央に揃える。`gltf-transform` で meshopt 圧縮。`ASSETS.md` に各モデルの出典とライセンスを記録
- `quality` プラグイン：L0～L4 の 5 段階の描画レベル（アンチエイリアス、2.5D、モデル、影などを制御）。初期レベルは `@pmndrs/detect-gpu` で推定し、実行時は FPS を基準に、低い状態が続けば自動で下げる（同ライブラリのベンチマークデータ元は更新を停止しているため、初期値の決定にのみ使う）
- パフォーマンスオーバーレイに draw call 数を追加
- デモ 7 を 3D フェンスに拡張。デモ 8「3D 建物」：draw call 数を表示。デモ 9「画質の自動調整」：現在のレベルと FPS を表示

**関門 4**：デモ 8 が L4 で滑らかに動く。FPS を意図的に制限するとデモ 9 が自動でレベルを下げる。3D コンテンツを含む地図を破棄した後も leak-bench が成功する（geometry、material、texture がすべて解放される）。

## レベル 5：アプリケーション層と AI アシスタント

目標：「SDK を作れるだけでなく、それを使ってプロダクトも作れる」ことを示し、AI × IoT × 医療の方向性を見せる。

- `@indoorkit/react`：`<IndoorMap>` コンポーネント、`useIndoorMap`、`usePlugin`（React 19）
- `apps/rtls-dashboard` リアルタイム位置情報ダッシュボード：資産一覧 + 地図 + 警報ストリーム + AI チャット
- 任意の `DataProvider`：Node の WebSocket サーバーで、フロントエンドとバックエンドの分離を示す
- `@indoorkit/ai`
  - プラグインは `tools`（名前、説明、zod のパラメータ）を宣言できる。zod v4 の `z.toJSONSchema()` でツール定義を生成し、モデル提供元ごとの互換性のため `$defs` をインライン化
  - 照会系ツール（`findNearest`、`whereIs`、`listAlerts`）は即時実行。操作系ツール（`planRoute`、`setFence`）はまず地図上でプレビューし、ユーザーが確認してから反映
  - モデルアダプター：Anthropic と OpenAI 互換 API。オンラインデモはユーザー自身の API キーを使う（ブラウザから直接呼び出し、キーはローカルにのみ保存）
  - 標準では内蔵の録画再生を使うため、キーがなくてもオンラインデモを最後まで体験できる
- デモ 12「AI 地図アシスタント」：「3階で一番近い車椅子は？」「ICUまで案内して」など。ページにツール呼び出しの記録を表示

**関門 5**：ダッシュボードが GitHub Pages 上でキーなしで動く（再生モード）。キーを入力すると実際の対話ができる。操作系ツールは確認なしでは反映されない。

## レベル 6：ドキュメント・公開・拡張

目標：計画中の全機能を揃え、他の人が使えるオープンソースプロジェクトにする。

- ドキュメントサイト：VitePress + TypeDoc による API リファレンス。README は日本語 / 英語の 2 言語。30 秒のデモ GIF
- 公開：Changesets で複数パッケージのバージョンを管理し、npm に公開
- 屋外ベースマップ：標準は OpenFreeMap（キー不要だがサービス保証なし）、予備として狭い範囲の Protomaps PMTiles ファイルを自前でホスト
- 地図グリフ：独自の欧文フォントが必要な場合は font-maker で glyph PBF を生成。アイコンは spreet でスプライト化
- 任意の `3d-tiles` プラグイン：3d-tiles-renderer を MapLibre のカメラと同期。PLATEAU の都市モデルを屋外の背景に使う（glTF の `CESIUM_RTC` オフセットの処理が別途必要）
- devtools：未解放リソース数、draw call、レイヤー一覧のパネル
- テストマトリクス：「ブラウザ × 画質レベル × デモ」の各セルを検証してから公開
- ナレッジベース：`docs/kb/`（ResourceTracker、ThreeLayer の座標換算など）。ドキュメントサイトの素材としても使う

**関門 6**：npm から `@indoorkit/*` をインストールできる。ドキュメントサイトが公開されている。12 のデモとダッシュボードがすべて動作する。テストマトリクスがすべて成功する。
